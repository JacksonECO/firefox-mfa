Exemplos de teste do autopreenchimento

Páginas estáticas (HTML + CSS + JS vanilla, sem rede) que simulam telas de login com campo de código OTP — e, no fim, telas de login com e-mail e senha — para testar o autopreenchimento da extensão MFA Num Toque. Cada página usa uma estrutura de input diferente.

Para que serve

O autopreenchimento (opt-in) injeta apenas o código de 6 dígitos — nunca o segredo — no(s) campo(s) da aba ativa, usando um seletor CSS que você configura na extensão. Estas páginas dão alvos reais para validar cada formato de campo e cada seletor.

Como o autopreenchimento decide

Quando há exatamente 1 MFA para o domínio, a extensão roda document.querySelectorAll(SEU_SELETOR) na página e:

  1. 1 elemento casado → escreve o código inteiro (ex.: 482913) nesse input.
  2. ≥ 6 elementos casados → modo "um dígito por caixa": um dígito em cada um dos 6 primeiros.
  3. 2 a 5 elementos → cai no modo de campo único e joga os 6 dígitos no primeiro input (ver exemplo 7).

Em todos os casos dispara input e change (para frameworks reconhecerem o valor) e, no último campo, dispara Enter para tentar enviar o formulário.

Como testar

  1. Abra a página de exemplo desejada no Firefox.
  2. Na extensão, ative o autopreenchimento e cole o seletor indicado na página (há um botão "Copiar").
  3. Tenha 1 MFA cadastrado para este domínio (ex.: localhost ou 127.0.0.1, conforme você sirva os arquivos).
  4. Abra o popup da extensão na aba: o código deve ser injetado nos campos.
  5. O Enter disparado abre um modal mostrando o código montado, quantos campos foram preenchidos e quantos eventos input/change ocorreram.

Você também pode digitar à mão e apertar Enter (ou clicar em "Verificar") para ver o mesmo modal — útil para comparar com o resultado da extensão.

Páginas de exemplo

  • 1. Campo único com atributo padrão

    Um input com autocomplete="one-time-code" (padrão de fábrica).

    input[autocomplete="one-time-code"]

  • 2. Campo único por id

    Um input identificado por id="otp".

    #otp

  • 3. Campo único por name

    Um input identificado por name="code".

    input[name="code"]

  • 4. Campo único por classe

    Um input com classe estável codigo-2fa.

    input.codigo-2fa

  • 5. Seis caixas com a mesma classe

    6 inputs de 1 dígito, classe otp-box (modo dígito-por-caixa).

    .otp-box

  • 6. Seis inputs dentro de um container

    6 caixas sem classe própria, miradas pelo container pai.

    #otp-container input

  • 7. Quatro caixas (caso de borda)

    Menos de 6 caixas → fallback: 6 dígitos na primeira caixa.

    .pin-box

  • 8. Múltiplos seletores por vírgula

    Um seletor único que tenta vários formatos de uma vez.

    input[autocomplete="one-time-code"], #otp, input[name="code"]

  • 9. Seis caixas com id sequencial

    6 caixas com id único e contador (token-input-mfa-0…5), casadas por prefixo.

    input[id^="token-input-mfa-"]

  • 10. Dois esquemas de id numa config só

    Outro prefixo (token-input-token-0…5); mostra como cobrir os dois esquemas combinando prefixos por vírgula.

    input[id^="token-input-mfa-"], input[id^="token-input-token-"]

Login (e-mail e senha)

Como o autopreenchimento de login decide

Além do código, a extensão preenche e-mail/usuário e senha da conta principal do domínio. Ela procura o campo de senha e o de usuário pelos seletores configurados (há padrões que cobrem a maioria dos sites) e:

  1. ignora campos invisíveis, desabilitados, somente-leitura e type="hidden";
  2. se o seletor de usuário não casar, usa o campo de texto visível imediatamente anterior ao de senha no mesmo formulário;
  3. escreve pelo setter nativo de value antes de disparar input/change, para formulários controlados por framework reconhecerem o valor;
  4. não envia o formulário — o Enter só é disparado se você ligar a opção.

A senha vai do processo de fundo da extensão direto para a página: ela nunca passa pelo popup. Nas páginas abaixo, o modal mostra a senha sempre mascarada.

  • 11. Login clássico: e-mail + senha

    type="email" + type="password" — coberto pelos seletores padrão.

    input[type="email"] · input[type="password"]

  • 12. Campos atípicos (fallback e override)

    Usuário sem atributo reconhecível, mais campos escondidos como ruído.

    #ident
