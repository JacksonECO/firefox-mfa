12. Login com campos atípicos (fallback e overrides)

O campo de usuário é um type="text" com name genérico (ident) — nenhum seletor padrão o encontra. Serve para testar as duas saídas: o fallback automático e o seletor por domínio.

O que esperar

  1. Sem configurar nada: o seletor de senha casa, o de usuário não. A extensão então usa o campo de texto visível imediatamente anterior ao de senha no mesmo formulário — que aqui é o campo certo. O checkbox e o campo escondido acima dele são ignorados.
  2. Com override por domínio (Configurações → Autopreenchimento de login → Adicionar domínio), o seletor abaixo mira o campo diretamente:
#ident

O modal também informa se a escrita usou o setter nativo de value — o caminho que formulários controlados por framework reconhecem.
